# Workflow 06: Seller Listing (إدارة عروض البائع)

**الفاعلون:** Seller.
**المحفّز:** البائع يضغط "إضافة عرض جديد" من لوحته (بعد `01-onboarding.md`).
**الشروط المسبقة:** تسجيل دخول كبائع. **KYC يُفحص عند النشر الفعلي** (الخطوة 3).

---

## أ. إنشاء عرض جديد

### 1. إدخال بيانات العرض
- البائع يدخل: `total_weight_grams`, `karat` (18/21/22/24).

### 2. حساب السعر المرجعي
- سيرفرياً، **قبل** الحفظ: `base_price_per_gram = آخر سعر لحظي عيار 24 × (karat / 24)` — يُعرض للبائع كمرجع فوري، مو شي يدخله يدوياً (المنصة تضمن تسعير عادل وموحد، البائع ما يقدر يحدد سعره الخاص).
- `available_weight_grams = total_weight_grams` (عند الإنشاء، كامل الكمية متاحة).
- `status = 'active'`.

### 3. النشر
- **Endpoint:** `POST /api/listings`
- **فحص KYC سيرفري إجباري هنا** (`KycVerified == true`؟):
  - إذا `false` وهذا **أول عرض** للبائع → يوقف وينتقل لـ `02-kyc-verification.md` (قسم ب)، وبعد التوثيق يرجع تلقائياً ويكمل النشر بنفس البيانات.
  - لو موثق مسبقاً (من عرض سابق) → ينشر العرض فوراً بدون أي وقفة.
- العرض يصبح ظاهر فوراً بقوائم `03-market-browsing.md` للمستثمرين.

---

## ب. ترويج عرض (Promoted Listing)

### المحفّز
البائع يضغط "روّج هذا العرض" من صفحة إدارة عروضه.

### الخطوات
1. النظام يعرض تفاصيل الرسم المقطوع (قيمة ثابتة، Config Value سيرفري — غير قابلة للتعديل من الـ Client).
2. البائع يضغط "ادفع وفعّل" → **Endpoint:** `POST /api/listings/{id}/promote`.
3. السيرفر ينادي داخلياً `POST /api/payments/mock` (دفع وهمي بالكامل، يرجع نجاح فوري `200` بدون بوابة دفع حقيقية — انظر ملاحظة تصميم بمستند API Design v2).
4. بعد نجاح الدفع: `is_promoted = true`, `promotion_expiry_date = now() + مدة الترويج المحددة`.
5. العرض ينتقل فوراً لأعلى نتائج البحث (`sort=promoted_first` بـ `03-market-browsing.md`).

---

## ج. تعديل/تعليق عرض

- **Endpoint:** `PATCH /api/listings/{id}` — البائع (المالك فقط) يكدر يغيّر `status` إلى `Suspended` (سحب مؤقت) أو يرجعه `Active`.
- **لا يوجد حذف (Delete)** — نفس منطق عدم حذف `Transaction`، أي عرض له تاريخ صفقات مرتبط به يبقى بالنظام دائماً (Audit trail)، السحب يصير بالـ `Status` بس.

---

## بعد إتمام هذا الـ Workflow
- عرض جديد (أو محدّث) موجود بحالة `Active` وظاهر للمستثمرين، أو عرض مروّج يظهر بالأعلى.
- البائع يكدر يراقب عروضه ويشوف الصفقات اللي صارت عليها (رابط لـ `08-ownership-portfolio.md`، قسم البائع).

## حالات الخطأ
| الحالة | السلوك |
|---|---|
| KYC غير موثق وقت أول نشر | `403 KYC_NOT_VERIFIED` + توجيه لـ Workflow 02 |
| محاولة تعديل عرض ما يملكه البائع | `403 Forbidden` |
| فشل الدفع الوهمي (نادراً، للاختبار فقط) | العرض يبقى `is_promoted = false`، رسالة خطأ بسيطة |

## Entities المرتبطة
`AssetListing` (إنشاء/تحديث) · `User.kyc_verified` (قراءة/تحديث)

## Endpoints المرتبطة
`POST /api/listings` · `PATCH /api/listings/{id}` · `POST /api/listings/{id}/promote` · `POST /api/kyc/seller` · `POST /api/payments/mock` (داخلي)
